# Just Keep Swimming — demo frontend

Interactive demo of the two Grover searches: **where am I?** (localization) and **how do I get home?** (route planning).

## Run

No build step. Serve the folder and open it:

```bash
cd frontend
python3 -m http.server 8000   # then open http://localhost:8000
```

Opening `index.html` directly also works. Fonts and the 3D view load from CDNs (Google Fonts, jsDelivr three.js 0.128), so 3D needs internet.

## Use

- **Drag** Robo to drop it anywhere (2D or 3D); **right-click** a square to set home.
- Press **Start mission**: Robo scans, runs Grover, decides whether to rescan or plan, draws the route
  from every place it might be, and walks it, narrating each step in the caption bar over the map.
- Under the map: **Auto / Step** (Step pauses at every beat; press **Next step**), **Restart**, and
  **Quantum vs classical** (the summary pop-up, also shown when the mission ends).
- Top bar: indoor / outdoor map, 2D / 3D view, **Ideal / Noisy**, and **Stats** (classical checks vs quantum
  calls, qubits and gate costs per search, in a separate panel).

## Files

Plain scripts loaded in order (they share globals):

| File | What it does |
|---|---|
| `js/world.js` | Map walls, rooms, themes, move/sense rules, candidates, plans, Grover maths (`bestK`, `theory`), shared state `S`, `tween` |
| `js/map2d.js` | 2D floor plan / topo map rendering: walls, doors, labels, heat map, superposition ghosts, trail, home marker, robot |
| `js/view3d.js` | three.js scene: walls, robot, sensing rays, amplitude columns, ghost robots |
| `js/search.js` | Amplitude chart, animated Grover loop with the Superposition → Oracle → Diffuser → Measure stepper |
| `js/panel.js` | Robo's face, caption bar, stage cards, stats panel, quantum-vs-classical pop-up |
| `js/story.js` | Autopilot mission (Auto / Step pacing): setup, scan, locate, decide, plan legs, draw routes, walk |
| `js/main.js` | Toggle wiring and startup |
| `js/qdata.js` | Qiskit results (generated by `experiments/precompute_ui.py`) |
| `css/styles.css` | All styles |

## Where the numbers come from

- `js/qdata.js` holds real Qiskit results for this building, generated by `python -m experiments.precompute_ui`
  from the project root (it reads `WALLS` from `js/world.js`, so the UI and Qiskit always agree).
- **Ideal** toggle: exact Qiskit statevector results. **Noisy · FakeTorino**: Qiskit Aer with the
  FakeTorino noise model, compiled oracle, k capped at 2 (noise moves the best k down).
  The amplitude chart animates the ideal oracle/diffuser steps; the heat map and chosen route
  come from the Qiskit data. If `qdata.js` is missing, the page falls back to in-browser ideal maths.
- Stage 2 uses the project scope: **3 moves = 64 plans = 6 qubits** per leg. If no plan reaches
  home from every possible position, Robo first searches for a plan that brings every copy to
  the same waypoint nearest home (so it learns where it is), then plans the next leg.
- Qubit counts shown are for the honest Bennett oracles: localization 4 position + 4 wall qubits
  per scan; planning 6 plan qubits + 4 position + one flag per possible start.
- In noisy mode a bad route can win the vote; Robo then walks it and visibly misses.
